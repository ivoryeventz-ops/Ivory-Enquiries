# Ivory Enquiries

Installable phone app for Ivory's enquiry book. `index.html` (repo root) is the thin wrapper that opens the Google Apps Script web app inside a frame; the icons and `manifest.webmanifest` make it installable.

## apps-script/

These two files are the Apps Script project attached to the **Ivory Enquiry Book** Google Sheet (Extensions > Apps Script). They are kept here as the source copy; deploying is done in Google.

- `Code.gs` - back end (enquiries, quotes, vendor ticks, Vendor list, reminders)
- `Index.html` - the app screen (create it in Apps Script as an HTML file named `Index`)

After changing either file in Apps Script: Deploy > Manage deployments > edit > New version.

## Vendor list > Not assigned

Opens from the **Vendor list** button. Lists, for every confirmed work, each outside-vendor item that has no vendor name yet (the 12 standard vendors plus anything under "Outside Vendors" in the latest quote), grouped by work and date. Decor package items are never listed, and items marked "Included in Package" are left out. Type a name next to an item and it saves to the Vendors tab straight away. No changes to `Code.gs` were needed for this view.

## No quote given + action reminders

- **No quote given:** a Confirmed work with no quote (neither a Google Site quote on the Quotes tab nor a page in ivory-packages) shows "No quote given yet" under its status. Use the **No quote given** chip to list them all.
- **Reminders:** each Confirmed work shows what is due and not yet ticked - 3 days before (wedding timeline, vendor checklist, payment & advance details), 1 day before (checklist to staff), day after (final payment details). Tick them on the card or inside the work; ticks are saved in a new **Actions** tab, shared by both phones. Use the **Action due** chip to see only works with something pending. A finished wedding stays on the list for 7 days while its day-after task is pending.
- **Signage board details:** a 3-days-before task, listed right after the wedding timeline. Ticks save the same way as the others.
- **Wedding timeline auto-tick:** the "Wedding timeline to be given" task shows ticked by default once a client page exists in the `ivory-wedding-timeline` repo. A folder counts when it shares a name word with the client and its page mentions the work's event date, so two weddings for one client never share a tick. A tick you save (or an un-tick) always overrides the default.
- Needs both `Code.gs` (new `api_flags` and `api_action`) and `Index.html` updated in Apps Script. The signage task and the timeline auto-tick are `Index.html` only.
- **Actions appear only when due:** inside a work, each stage (3 days before, 1 day before, day after) is shown only from the day it needs action - no "in 2 days" placeholders. Actions sit at the bottom of the work, below the quotes and outside vendors, so they never push the quotes down.
- **Opening a work is instant:** the last quotes/vendors shown for a work appear immediately and are refreshed quietly behind them (never redrawn while someone is typing or has an unsaved vendor change).
- **Vendors follow the latest quote:** opening a work or the Vendor list re-reads the quote pages (at most every 90 seconds), so a re-issued quote updates the outside-vendor list. "Anchor / MC", "LED Wall" and "Tall Men Security" are now standard outside vendors (Photo Booth is not), and "Ambient" lighting is recognised as well as "Ambiance". New vendor types need `Index.html` only; `Code.gs` also lists them.
- **Migrate quote:** a Confirmed work whose quote exists only as a Google Site still counts as quoted, but shows an amber warning, because outside vendors are picked automatically only from GitHub quotes. The **Migrate quote** chip lists them. The warning goes away once a GitHub quote is issued for that work.
- **Payment details:** inside a work, a **Payment details** row sits on top of *Quotes sent*, above the latest quote. It opens a sheet pre-filled from the latest quote in ivory-packages (name, date, venue, the decor package rate (from the package total on the page, or a package price line) and each additional service's rate). Rates, Total, Discount and Advance Received are all editable, and **+ Additional advance received** adds more advance lines (label such as "Advance Received on 23 Oct" plus amount). Balance is worked out live. **Save & publish** writes `<Client>/payment.html` in the packages repo (same folder as the client's quotes; page format matches `Christy/payment`), then offers **Send on WhatsApp** and **Open page**. Opening it again loads what was saved (older hand-made payment pages are read too). A *Sent* tag shows on the row once a payment page exists. The GitHub key (fine-grained, Contents read/write on Ivory-Packages) is asked for once, the first time anyone publishes, and kept in the Apps Script project's Script Properties (`GH_KEY`), so both phones use it and nobody is asked again; a rejected key is cleared and asked for again. Needs `Code.gs` (new `api_pay_status` and `api_pay_publish`) and `Index.html`; after pasting `Code.gs`, run any function once from the editor (or just publish) and approve the "connect to an external service" permission. With an old `Code.gs` the app falls back to a key stored on each phone.
- **Edit as new quote:** every quote in *Quotes sent* has an **Edit as new quote** button (a work with no quote gets a **New quote** row instead). It opens the quote page as an editable form: name, wedding date, venue, the stage photo (keep the current one, pick another image already in the client's folder, upload a new one, or none), every section, inclusions list, priced line (name, details, note, rate, quantity) and rate card. **Add from packages** lists all 13 packages and every add-on from the quote builder with its default rate: a package sets the *Decor Package* rate card (and fills the standard inclusions if that section has none), an add-on becomes a line you can edit (quantity multiplies the rate). **Other services** at the bottom is a blank area for anything not in the list, with its own rate. **Preview** shows the page; **Save as new quote** writes `<Client>/<YYMMDD>.html` in the packages repo, so the old quote is never changed. The new number is today's date; if a quote with that number already exists for the client, saving is blocked unless **replace** is ticked. The page uses the Abraham quote theme and never shows a grand total: Grand Total / Discount / Total rows from the old quote are left out because they would go stale when rates change (the Payment details page still handles discount and advance). The free-services section is regenerated (hostess note dropped when an Anchor / MC line is added). Needs `Code.gs` (new `api_quote_publish`, uses the same GitHub key as Payment details) and `Index.html`. Not done by this screen: adding the quote as a tab on the client's Ivory-Events intro link (the quote builder still does that).
- **Stage designs in the quote editor:** *Choose a stage design* shows every stage photo from the quote builder (all 13 packages, 48 photos, hosted in Ivory-Packages under `stages/`). Tapping one uses it as the quote's stage photo and links that package (its rate goes into the Decor Package rate card). The *Migrate quote* filter was removed - all quotes are on GitHub now.
- **Add-ons and total in the quote editor:** *Services from the quote builder* is an always-visible tick-list grouped like the builder (church decoration, hall decor, cake, special effects, band, cars, etc.; search box on top). Ticked services appear in *Add-on services*, a section printed after the Decor Package; tick again to remove; typed lines go in the same section. An old *Discounted package rate* card is shown as *Decor Package*. Optional **Show a total after the add-ons** (label editable, default "Total") adds one total row = Decor Package rate + add-ons (a section with a rate card counts at that rate, others by their priced lines); the amount is recalculated every time the quote is saved, and is off unless ticked.
- **Stage design photo (share):** the *Stage decoration list* screen now also shows the quote's stage design photo with a **Share stage design photo** button. It loads the image from the quote as a real file and opens the phone's share menu, so WhatsApp gets the photo itself, not a link. If the phone/browser blocks sharing from inside the app, **Save photo to phone** downloads it to attach manually. Quotes with no stage photo show nothing extra. `Index.html` only (version v18-Nov-e).
- **Clean-up and tabs (v19-Nov-a):** the list now shows each work as a card with a date tile; **Vendor list** moved to the top bar. Opening a work shows status, then four tabs: **Quotes** (dated, latest first, with Edit as new quote and the Stage decoration list), **Client link**, **Vendors** and **Tasks** (the last two only for Confirmed works). Every earlier feature is still there, just grouped. `Index.html` only for the look; the two features below also need the new `Code.gs`.
- **Client link tab:** the client's one page is `ivory-events.pages.dev/New A/<Client>/` (Ivory-Events repo, `data.json` drives its tabs). This tab lists, in order: each quote (dated, latest first), the Wedding timeline (shown once "Send the wedding timeline to the client" is ticked; same tick as the Tasks reminder), then Payment. Each item has its own **Add to link** button and nothing goes live until you tap **Confirm and add** on that item. A quote that is not yet on the link, a timeline and a payment page are three separate confirmations. Needs `Code.gs` (`api_site_status`, `api_site_tab`) and a GitHub key with Contents read/write on **Ivory-Events** (asked once, kept in Script Properties as `SITE_KEY`; the timeline or payment key is used if it already reaches that repo). The client page itself needs the updated `New A/generate.py` / `client-shell.html` from Ivory-Events so that Timeline and Payment tabs appear after the quote tabs.
- **Staff checklist (Tasks tab):** **Make checklist** lists the items from the latest quote (stage and decor, using the same rules as the Stage decoration list, plus the outside vendors with the names and details typed in the Vendors tab). Untick what staff do not need, add your own lines, then **Create Google Sheet** (confirmed first). The sheet is saved in a Drive folder "Ivory Staff Checklists", has a Done tick box per item, and anyone with the link can tick items. Then **Send on WhatsApp** shares the link, and **Mark "Checklist to staff" as done** ticks the 1-day-before reminder. The last sheet made is remembered in a new **Checklists** tab so both phones see it. Needs `Code.gs` (`api_chk_get`, `api_chk_create`); after pasting it, run any function once from the editor and approve the new Google Drive permission. To give named staff edit access, list their emails in `STAFF.EMAILS` at the top of `Code.gs`; set `STAFF.ANYONE_WITH_LINK` to `false` to stop link sharing.
- **Event type + automatic client link (v20-Nov):** *New enquiry* now has an **Event type** (Wedding - Christian, Wedding - Pentecost, Engagement, Reception - Hindu). Saving makes the client's link straight away in Ivory-Events > `New A/<Client>/` (page + `data.json` with the type), then a box offers **Send on WhatsApp** (opens WhatsApp with the intro message and link; pick the contact) and **Open**. The type decides the Packages and Service Checklist pages: Christian = `New A/parts/`, Pentecost = `parts/pentecost/` (P items, New A look), Engagement = `parts/engagement/` (E items), Hindu reception = `parts/hindu/` (E items, headed "Reception"). For an existing work, the **Client link** tab has an **Event type** picker with **Make link** / **Change**, and a **Send on WhatsApp** button. A returning client who already has a link keeps it (type changes only from that tab). Needs `Code.gs` (new `api_site_create`) and `Index.html`; the GitHub key for Ivory-Events is asked once if the script has none.
- **Staff checklist sheet format (v20-Nov):** the Google Sheet now matches "Wedding Setup Checklist": Done | Item | Qty | Details, green header, section bands, "x of y jobs done" counter, and ticking a box turns the row green, grey and struck through. Needs `Code.gs`.
- **No more "GitHub answered 403" (v20-Nov-b):** the quote and timeline file lists are now read by the script with the saved GitHub key (`api_gh_tree` in `Code.gs`) instead of by each phone with no key, which GitHub limits to 60 requests an hour per network. Needs `Code.gs` and `Index.html`.
- **Staff checklist sheet, simplified (v20-Nov-c):** only Done (tick) | Item | Details, in the green of the Wedding Setup Checklist sheet. No section rows, no Qty column, no vendor names (outside vendors appear as plain items). Ticking a box strikes the item and details through and turns the row pale green. Needs `Code.gs` and `Index.html`.
- **Permission error on checklist (DriveApp.createFolder):** run `authorizeAll` once from the Apps Script editor and approve Drive access, then Deploy > Manage deployments > edit > New version.
- **Staff checklist sheet (v20-Nov-d):** Qty column is back (Done | Item | Qty | Details). Qty is guessed from the item text (e.g. "2 nos") and can be typed or fixed in a box on each row before the sheet is made. The sheet is named `Ivory Checklist - <venue> - <d MMM yyyy>` (client name if there is no venue).
- **No client link filter (v20-Nov-e):** a **No client link** chip sits beside *No quote given* and *Action due*. It scans every work (except Lost) and lists those whose client folder has no page in Ivory-Events > `New A`; each such card also shows "No client link yet". The folder is the one the work's quotes are in, else the first word of the name. Making the link (new enquiry or Client link tab) removes the flag at once. `Index.html` only.
- **No client link, same-name check (v20-Nov-f):** when two or more works share the same first name, the link must also be for that work's wedding date (read from `wedding_date` in the link's `data.json`); a link folder whose words all appear in the name (e.g. `Christy-Kzy` for "Christy Kzy") is also considered. A link with no readable date is accepted. `Index.html` only.
- **Make link from the list (v20-Nov-g):** a work flagged "No client link yet" now has an event-type picker and a **Make link** button on its card (works that were added in the sheet or before the automatic link existed). One tap makes the client's link, then offers Send on WhatsApp. A work with no date asks for the date first. `Index.html` only.
- **Own link for every enquiry (v20-Nov-h):** a new link no longer reuses another client's folder. If the first-name folder (e.g. `Jaison`) already belongs to a different wedding date, the new one is made as `Jaison-YYMMDD`. If saving an enquiry cannot make the link (key prompt cancelled), a message says so and the card keeps its **Make link** button. `Index.html` only.
- **Own outside vendors (v27-Nov-a):** the **Vendors** tab now shows for every work (except Lost), with or without a quote. **Add an outside vendor** takes a service and an optional vendor name. These are saved with a "+ " in front (hidden on screen), so they are never removed when the quote changes, and each has its own **Remove** button. They appear in Vendor list, and in the staff checklist and Not assigned for Confirmed works. Quote-picked vendors still show only for Confirmed works. `Index.html` only.
- **Services-only quote (v27-Nov-a):** in the quote editor, tick **Services list only - no packages, rates or photos**. It is saved like any quote (new quote number; the priced quote is not changed unless **replace** is ticked). Payment details keep reading the latest quote that has rates. `Index.html` only.

## Push notifications: what is due

`doGet(e)` also answers `?push=due&key=<PUSH_KEY>` with one digest of the 3-days-before / 1-day-before / day-after tasks that are not ticked yet (JSON: `count`, `title`, `body`). The Cloudflare push worker in the `Process` repo calls it every morning and sends the result to both iPhones. `PUSH_KEY` is a Script Property you set yourself. Full steps: `PUSH-SETUP.md` in the `Process` repo.
